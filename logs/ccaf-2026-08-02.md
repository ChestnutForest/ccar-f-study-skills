## Q. Windows で Git を使うとき、CRLF 警告はどう扱うべきか？

**A. `.gitattributes` に `* text=auto eol=lf` を置けば警告が止まる。ただし警告自体は無害。**

Windows の Git は既定で `core.autocrlf=true` のため、LF で書かれたファイルを add すると `LF will be replaced by CRLF the next time Git touches it` という警告が全ファイル分出る。

これは error ではなく**変換が起きることの通知**である。重要なのは、**リポジトリの中には LF のまま保存され、作業ディレクトリだけが CRLF になる**という点。環境をまたいで同じリポジトリを共有しても、行末差分でファイル全体が変更扱いになるのを防ぐ仕組みである。

`.gitattributes` に `* text=auto eol=lf` を置くと、「テキストファイルはリポジトリ内で LF に統一する」と宣言でき、警告が出なくなる。既にコミット済みのリポジトリに後から追加する場合は、`git rm --cached -r .` でいったんインデックスから外し（**ファイル自体は消えない**）、`git add .` で入れ直す必要がある。

## Q. GitHub の Markdown にコピーボタンを設置できるか？

**A. 独自のボタンは設置できない。ただしコードブロックには GitHub 標準のコピーアイコンが付く。**

GitHub は Markdown 表示時に HTML をサニタイズし、`<button>`・`onclick` などのイベント属性・`<script>` をすべて除去する。リポジトリの Markdown で JavaScript が動くと閲覧者のブラウザで任意コードが実行できてしまうため、セキュリティ上の措置である。

**代替手段**：コードブロック（``` で囲んだ部分）には、GitHub が**標準でコピーアイコンを右上に表示する**。長いプロンプトを配布したい場合、本文全体を ```text で囲めばワンクリックでコピーできる。

トレードオフとして、コードブロック内では太字や見出しが記号のまま表示される。ただし NotebookLM のようなツールに貼り付ける用途では、むしろ記号込みのプレーンテキストのほうが確実である。
