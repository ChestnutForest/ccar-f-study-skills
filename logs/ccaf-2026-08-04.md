# Q&A 形式の知識カード（技術知識）

## Q. Claude Code の API プロバイダーは何種類あり、それぞれどういうときに選ぶのか？

**A. 5種類。既定の推奨は Claude for Teams / Enterprise。クラウド3社（Bedrock / Google Cloud's Agent Platform / Microsoft Foundry）を選ぶ動機は、いずれも「既存のコンプライアンス統制と課金の継承」である。**

| プロバイダー | 選ぶ条件 |
|---|---|
| **Claude for Teams / Enterprise** | Claude Code と claude.ai を、運用すべきインフラなしに1つの席単位サブスクリプションでまとめたい。**これが既定の推奨** |
| Claude Console | API 優先である、または従量課金（pay-as-you-go）にしたい |
| Amazon Bedrock | 既存の **AWS** のコンプライアンス統制と課金を継承したい |
| Google Cloud's Agent Platform | 既存の **GCP** のコンプライアンス統制と課金を継承したい |
| Microsoft Foundry | 既存の **Azure** のコンプライアンス統制と課金を継承したい |

**選択が波及する4領域**：`Your choice affects billing, authentication, which compliance posture you inherit, and which Claude Code features your developers can use.` つまり課金・認証・統制・**機能可用性**を同時に決めてしまう。前日に読んだ Administration overview で5つの決定が「上流の選択が下流を制約する順」に並んでいたのは、この波及があるためである。

**クラウド3社の共通点**：3行がいずれも `You want to inherit existing ~ compliance controls and billing` で統一されている。新たに統制を作るのではなく、**既に監査を通っている既存環境の枠組みをそのまま使う**ことが動機。金融・医療など規制の厳しい業界で現実的な選択肢になる。

（出典: Claude Code Docs「Choose your API provider」／学習日 2026-08-04）

## Q. クラウド経由で導入すると使えなくなる Claude Code 機能があるか？

**A. ある。ウェブ版・Routines・Code Review・Remote Control・Chrome 拡張は、Console API キーやクラウド認証情報「だけ」では使えず、Claude.ai アカウント（Teams / Enterprise の席）が別途必要。**

原文は `Claude Code on the web, Routines, Code Review, Remote Control, and the Chrome extension are not available through Console API keys or cloud-provider credentials alone.`

**`alone` が効いている**。「それらだけでは」という限定で、否定文と組んで「〜だけでは足りない」という含意を作る。つまり Bedrock で導入しても、これらの機能を使いたければ **Teams / Enterprise の席を別途買う必要がある**。

本文自身が `If you deploy through Bedrock, Vertex, or Foundry, plan whether developers also need Claude for Teams or Enterprise seats.` と、**併用を前提とした計画**を促している。`also`（追加で）が「クラウド経由で導入したうえで、さらに」という意味を作る。

**実務上の含意**：導入設計の段階でこれを見落とすと、後から追加コストが発生する。本節で最も注意を要する箇所。

（出典: Claude Code Docs「Choose your API provider」／学習日 2026-08-04）

## Q. 複数プロバイダーを併用する場合、認証やログの分散をどう解決するか？

**A. LLM gateway を使う。複数プロバイダーの前面に単一のエンドポイントを置き、リクエストログを集中管理する中継層。**

原文は `If you want a single endpoint in front of multiple providers or centralized request logging, see LLM gateway.`

プロバイダーを増やすと認証情報やログが分散するため、それを1点に集約する仕組みが必要になる。`in front of ~`（〜の前面に）はプロキシ的に前段へ置く意。

なお **`Proxy and firewall requirements in Network configuration apply regardless of provider.`**（プロキシとファイアウォールの要件は**プロバイダーに関わらず**適用される）。`regardless of ~` は「〜に関わらず」で、プロバイダー選択の影響を受けない共通要件があることを示す。

（出典: Claude Code Docs「Choose your API provider」／学習日 2026-08-04）

# 【想定問題】全文（v10.3 形式）

本日の英文から生成した想定問題を、解説を含めて全文収録する。

**⚠️ 前提**：本文の主題（プロバイダー選択・課金・認証・クラウド統制）は公式ガイド §17 で明示的に試験範囲外のため、本来この英文からは出題されない。ただし末尾で触れられる「機能の可用性をどう設計するか」は導入判断として範囲に近づくため、その周辺で1問だけ作成した。

**判断軸**: 比例性（対処が問題の規模に見合うか）

## Scenario

> Your organization deploys Claude Code through Amazon Bedrock to inherit existing AWS compliance controls. Three months in, your developers report that they cannot use Code Review or the Chrome extension, and several have started pasting code into external tools instead. Your security team flags this as a data-handling risk.

## Question

> What is the most effective first step to address this?

## Options

> A. Purchase Claude for Teams or Enterprise seats for the developers who need those features, keeping the Bedrock deployment for API traffic.
>
> B. Migrate the entire deployment from Bedrock to Claude for Teams, abandoning the AWS compliance controls already in place.
>
> C. Build an internal proxy that replicates Code Review functionality using Bedrock API calls.
>
> D. Block access to external tools through network policy and instruct developers to work without those features.

## 正解と誤答の理由

**正解**: A。本文が明示するとおり、Code Review や Chrome 拡張は `not available through Console API keys or cloud-provider credentials alone` であり、**Claude.ai アカウント（Teams / Enterprise の席）が別途必要**。本文自身が `plan whether developers also need Claude for Teams or Enterprise seats` と、**併用を前提とした計画**を促している。既存の Bedrock 導入を維持したまま、必要な人にだけ席を追加するのが、問題の規模に見合った最小の対処である。

**誤答の理由**:
- **B** は過剰。AWS のコンプライアンス統制を継承するという当初の目的を、機能の可用性のために丸ごと捨てることになる。本文は両者の併用を想定しており、二者択一ではない。
- **C** は最も過剰設計。公式機能を自前で再実装する労力に対し、席を買えば済む問題である。保守負担も継続的に発生する。
- **D** は症状に対処しているだけで、根本原因（必要な機能が使えない）を解消していない。外部ツールへの流出はブロックできても、開発者の作業は非効率なまま。

### 【英語の型と語法】

- **動詞型 [VP3A]**（主語＋自動詞＋前置詞＋名詞）
  → 該当箇所: `flags this as a data-handling risk`
  → ※厳密には flag は他動詞（VP6A）だが、`flag A as B`（A を B として指摘する）という前置詞 as を伴う構文。`regard A as B` / `see A as B` と同型。
  → 構文と修飾: `Your security team`(S)＋`flags`(V)＋`this`(O)＋`as a data-handling risk`(M・資格・立場)。
  → カード: 〔②語法カード〕表「セキュリティチームはこれをリスクとして指摘する」→ 裏 flags this **as** a data-handling risk（flag A as B）／米式✓

- **動詞型 [VP6A]**（主語＋他動詞＋名詞／代名詞）
  → 該当箇所: `deploys Claude Code` / `cannot use Code Review` / `address this` / `Purchase ~ seats` / `Migrate the entire deployment` / `Build an internal proxy` / `Block access`
  → 同型の例: Everyone likes her.
  → 構文と修飾: Scenario 第1文は `Your organization`(S)＋`deploys`(V)＋`Claude Code`(O)＋`through Amazon Bedrock`(M・経路)＋`to inherit existing AWS compliance controls`(M・**目的の to 不定詞**)。**目的を明示することで、選択肢 B（統制を捨てる）が的外れだと分かる仕掛け**になっている。選択肢はすべて動詞の原形で始まり、長さも揃えられている（公式サンプル問題と同じ書き方）。

- **動詞型 [VP6C]**（主語＋他動詞＋動名詞）
  → 該当箇所: `have started pasting code into external tools`
  → 同型の例: She enjoys painting.
  → start は動名詞・to 不定詞の**どちらも取れる**（start pasting / start to paste）が、習慣的な行動の開始には動名詞が自然。
  → 構文と修飾: `several`(S＝several developers の省略)＋`have started`(V・**現在完了**)＋`pasting code into external tools`(O＝動名詞句)＋`instead`(M)。**現在完了が「すでに始めてしまい、今も続いている」という緊急性を作る**。
  → カード: 〔③例文カード〕表「数名が代わりに外部ツールへコードを貼り付け始めてしまった」→ 裏 several **have started pasting** code into external tools instead.（VP6C／現在完了[5]）／米式✓

- **動詞型 [VP9]**（主語＋他動詞＋that節）
  → 該当箇所: `your developers report that they cannot use ...`
  → 同型の例: Do you think (that) it will rain?
  → report＋that 節。**VP10（間接疑問）との違い**は、that 節が「事実の報告」であるのに対し、whether / which 節は「不確定な事柄」を導く点。本文の `plan whether developers also need ...`（VP10）と対比すると識別しやすい。

- **動詞型 [VP17A]**（主語＋他動詞＋名詞／代名詞＋to不定詞）
  → 該当箇所: `instruct developers to work without those features`（選択肢D）
  → 同型の例: Do you want me to stay?
  → instruct＋O＋to 不定詞（O が〜するよう指示する）。**to 不定詞の意味上の主語は目的語（developers）**。
  → カード: 〔②語法カード〕表「開発者にそれらの機能なしで作業するよう指示する」→ 裏 **instruct** developers **to work** without those features（VP17A・意味上の主語は developers）／米式✓

**時と時制**
- **[1] 単純現在時制**（Simple Present）: `deploys` / `report` / `flags` / `need` / `replicates`。write の活用: He writes。相の意味＝**現在の恒常的な状況**。
- **[5] 現在完了時制**（Present Perfect）: `have started`。write の活用: He has written。相の意味＝**過去に始まり現在も継続・影響が残る**。
- **時制の枠外（命令形）**: 選択肢A〜Dの `Purchase` / `Migrate` / `Build` / `Block`。4択の書き出しを原形で統一するのが公式の書き方。
- **時制の枠外（法助動詞）**: `cannot use`（不可能）。
- **時制の枠外（準動詞）**: 目的の to 不定詞 `to inherit` / `to address`；動名詞 `pasting`；**付帯状況の分詞** `keeping ~`（選択肢A）・`abandoning ~`（選択肢B）；関係詞節内の `replicates`（選択肢C）。

### 【語彙・語法メモ】

- **Three months in**（副詞句）3か月が経った時点で。`in` が「（期間の）中に入って」を表す口語的表現。`Three months into the deployment` の短縮形。
- **flag A as B**（他動＋前置詞）A を B として指摘する・問題視する。以前読んだ Hooks の英文では `flag anything risky`（目的語のみ）だったが、ここでは as を伴う。
- **data-handling risk**（名句）データ取り扱い上のリスク。ハイフン複合修飾。
- **paste A into B**（他動＋前置詞）A を B に貼り付ける。前置詞は into（中へ）。
- **instead**（副）代わりに。文末に置いて、直前の行動が本来の手段の代替であることを示す。
- **address**（他動）（問題に）対処する。`address this issue`。
- **first step**（名句）最初の一手。**この語が「比例性」の軸を示す合図**（`ccar-f-keywords.md` §5）。過剰設計の選択肢を排除せよ、という指示に等しい。
- **keeping ~**（付帯状況の分詞・選択肢A）〜を維持したまま。**この分詞句が「既存を捨てない」という含意を作り、選択肢Aを正解にしている**。分詞構文の意味を取り違えると、AとBの差が見えなくなる。
- **abandoning ~**（付帯状況の分詞・選択肢B）〜を放棄しながら。keeping と正反対の含意。**AとBは同じ分詞構文の型でありながら、動詞の意味が逆**という対比構造。
- **already in place**（形容詞句・選択肢B）すでに整っている・導入済みの。`in place` は「所定の位置にある＝機能している」。
- **replicate**（他動・選択肢C）複製する・再現する。**公式機能を自前で作り直す**という含意を持ち、過剰設計のサインになる。
- **functionality**（名）機能（性）。
- **network policy**（名句・選択肢D）ネットワークポリシー。通信の許可・遮断の規則。
- **米式スペル変換**: 出題文はすべて米式（`organization` は英式 organisation の米式形）。変換対象なし。

### 【全訳】

**Scenario（シナリオ）**
あなたの組織は、既存の AWS コンプライアンス統制を継承するために、Amazon Bedrock 経由で Claude Code を導入しています。3か月が経った時点で、開発者から Code Review や Chrome 拡張が使えないという報告が上がり、数名は代わりに外部ツールへコードを貼り付けるようになってしまいました。セキュリティチームは、これをデータ取り扱い上のリスクとして問題視しています。

**Question（設問）**
これに対処するための、最も効果的な最初の一手はどれですか。

**Options（選択肢）**

A. それらの機能を必要とする開発者のために Claude for Teams または Enterprise の席を購入し、API トラフィック向けには Bedrock 導入を維持する。

B. 導入全体を Bedrock から Claude for Teams へ移行し、すでに整っている AWS コンプライアンス統制を放棄する。

C. Bedrock の API 呼び出しを使って Code Review の機能を複製する、内製のプロキシを構築する。

D. ネットワークポリシーによって外部ツールへのアクセスを遮断し、開発者にそれらの機能なしで作業するよう指示する。

**訳を並べて見える差分**：A だけが「既存を維持したまま（keeping）不足分を足す」構造になっている。B は「移行して放棄する（abandoning）」、C は「自前で複製する（replicates）」、D は「遮断して我慢させる」。**A 以外はいずれも、既にあるものを捨てるか、新たに作るか、諦めさせるか**であり、規模に対して不釣り合いである。

| **[5] 現在完了時制** | Present Perfect（He has written） | several **have started** pasting | 出題文 |
| **付帯状況の分詞** | 分詞句が主節に付帯情報を添える | **keeping** the Bedrock deployment（A）／**abandoning** the AWS controls（B） | 出題文 |

## 今日の型に関する気づき

**目的語に間接疑問節を取る VP6A**：本文の導入文 `Your choice affects billing, authentication, which compliance posture you inherit, and which Claude Code features your developers can use.` は、**同じ動詞 affects に、性質の異なる4つの目的語がぶら下がる**構造。前2つは単純な名詞（billing / authentication）だが、後2つは**間接疑問節**（which 節）。「課金に影響する」と「どの体制を継承するかに影響する」が並列される。which+名詞のかたまりが節内の目的語として前に出た形。

**VP9 と VP10 の識別**：`report that they cannot use ...`（VP9・that 節＝事実の報告）と `plan whether developers also need ...`（VP10・whether 節＝不確定な事柄）。**後続の節が「確定した事実」か「まだ決まっていないこと」か**で使い分ける。

**付帯状況の分詞が選択肢の正誤を分ける（v10.3 で解説対象に加えた成果）**：選択肢Aの `keeping the Bedrock deployment` と選択肢Bの `abandoning the AWS compliance controls` は、**同じ分詞構文の型でありながら動詞の意味が正反対**。この差を読み取れないと、AとBのどちらが「既存を維持する案」なのか判断できない。v10.2 までは選択肢を解説対象から外していたため、この論点は教材にならなかった。

**affect は他動詞**：`Your choice affects billing`。日本語の「〜に影響する」に引きずられて `affect to` としない。名詞形 effect との混同にも注意。**8/1 の Available scopes（`Who it affects`）に続いて2度目の出現**。

**変更の理由**：v10.2 では「選択肢は分量が多いため解説対象に含めない」としたが、これは誤った判断だった。

**【全訳】の追加理由**：4択の日本語訳を並置すると**選択肢間の差分が見えやすくなり**、なぜ1つだけが正解なのかが構造的に理解できる。本日の問題では「A だけが既存を維持したまま不足分を足す構造」という対比が、訳を並べて初めて明瞭になった。
