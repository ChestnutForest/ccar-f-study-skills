# NotebookLM スライド作成プロンプト

CCAR-F 学習ログ（`logs/ccaf-*.md`）を NotebookLM に取り込んだ上で、復習用スライドを生成するためのプロンプト。

- **対応スキル版**: english-parsing v10.2 / learning-asset v3.1
- **使い方**: NotebookLM のノートブックに `logs/` 配下の全ファイルをソースとして追加し、以下の本文をそのまま貼り付ける。
- **更新の目安**: english-parsing のブロック構成が変わったとき、または CCAR-F の公式ガイドが改訂されたとき。

---

## プロンプト本文（ここから下をコピーして使う）

全ソースを横断して、以下のスライドを作ってください。

CCAR-F（Claude Certified Architect – Foundations、試験コード CCAR-F、Version 1.0・2026年7月発効）の受験対策および TOEIC 学習のための、復習用スライドを作成してください。対象は、Anthropic 公式ドキュメント（Claude Code Docs・Claude Platform Docs・Anthropic Academy）の英文を毎日精読し、その内容と英文法（A.S. ホーンビーの英語の型）を「学びの資産化」として全日分蓄積している学習者本人です。

構成は次の順にしてください。

**(1) 表紙。**

**(2) CCAR-F の試験構造。** 5ドメインとその配点比率を一覧で示してください（Domain 1 Agentic Architecture & Orchestration が27%で最大、Domain 3 Claude Code Configuration & Workflows と Domain 4 Prompt Engineering & Structured Output が各20%、Domain 2 Tool Design & MCP Integration が18%、Domain 5 Context Management & Reliability が15%）。あわせて、試験形式（60問・120分・6シナリオから4つを提示・合格スコア720／100〜1000のスケール）と、この試験が暗記ではなく実践的判断を問うものであることを明示してください。

**(3) 公式サンプル問題に見る「判断の3軸」。** 公式ガイドのサンプル問題12問を分析すると、正解は次の3つの軸のいずれかで決まります。各軸について、どういう状況で問われ、何を選ぶのが正解かを示してください。

- **確実性**：失敗が許されない場面（金銭処理、本人確認など）では、プロンプトによる指示ではなくプログラム的強制（フック、前提条件ゲート）を選ぶ。
- **根本原因**：症状ではなく原因に当たる。下流のエージェントが正常に動いているなら、原因は上流の設計にある。
- **比例性**：対処が問題の規模に見合っているか。「最初の一手（first step）」を問われたら、低コスト・高レバレッジな施策を選ぶ。分類器の訓練や独自基盤の構築は過剰設計として誤答になる。

**(4) Claude Code の5つのカスタマイズ機能の比較。** CLAUDE.md・スキル・サブエージェント・フック・MCPサーバーを、「起動のトリガー」「コンテキストの置き場所」「確実性（決定論的か確率的か）」の3軸で比較する一覧を作ってください。

**(5) 設定スコープの4層。** Managed（サーバー管理設定・plist・レジストリ・システムレベルの managed-settings.json）／User（`~/.claude/`）／Project（リポジトリ内の `.claude/`）／Local（`.claude/settings.local.json`）について、場所・影響範囲・チーム共有の可否を一覧で示してください。特に次の3点を強調してください。

- User と Project の違いはパスの `~` の有無であり、適用範囲が根本的に異なること。
- 同じ Managed でも配布経路によって影響範囲が変わること（HKLM レジストリはマシン全体、HKCU は現在のユーザーのみ）。
- Local は Claude Code が書き込む際に自動で gitignore され、個人設定の誤コミットを機構的に防いでいること。

**(6) 「どんな症状が出たら、どの機能を使うか」の分岐条件。** 症状→機能の形で示してください。

**(7) 各機能につき1枚ずつ。** 定義・使うべきタイミング・具体例・注意すべき例外をまとめてください。特に次の2点は必ず含めてください。

- サブエージェントの権限継承（親の権限＋追加制限で必ず狭くなる）と、**サブエージェントはスキルを自動継承しない**という公式が gotcha として名指しした仕様。
- Explore・Plan が CLAUDE.md を読み込まない例外。

**(8) standalone 構成とプラグインの使い分け。** `.claude/` に直接置く standalone と、`.claude-plugin/plugin.json` を持つプラグインについて、スキル名の形式（`/hello` と `/plugin-name:hello`）、向く場面、名前空間のトレードオフを示してください。公式が推奨する段階的移行（まず standalone で素早く反復し、共有の準備ができたらプラグインへ変換する）も明示してください。

**(9) コンテキストウィンドウの構造。** 起動時に読み込まれる固定分と、作業中に積み上がる変動分の区別、および容量が尽きたときの2つの対処（圧縮と隔離）の使い分けを示してください。

**(10) 公式が名指しするアンチパターン。** 公式ガイドが「避けるべき」と明示したものを一覧にしてください（自然言語のシグナルでループ終了を判定する、汎用エラー "Operation failed" を返す、エージェントにツールを与えすぎる、モデルの自己申告 confidence でエスカレーションを判断する、感情分析で判断する、同じセッションで生成したコードを自己レビューさせる、大きなコンテキスト窓のモデルに変えて注意力の問題を解決しようとする、など）。これらは選択肢問題で誤答として現れやすいため、印象づける形にしてください。

**(11) ホーンビーの英語の型：識別ポイント。** 「同じ動詞が後続要素によって別の型になる」ケースを対比表で示してください。蓄積されたログから、少なくとも次を含めてください。

- keep が VP22／VP14／VP15A に分かれる例
- want が VP6A／VP7A／VP17A に分かれる例
- **VP8 と VP10 の識別**：後続が to 不定詞なら VP8（無時制）、主語＋動詞を持つ定形節なら VP10（`learn how to share` と `learn which approach fits which scenario`）
- VP9 と VP10 の識別
- **VP17A の意味上の主語**：to 不定詞の主語は文の主語ではなく目的語（`Configure custom subagents to use specific skills` では subagents がスキルを使う）

**(12) 試験特有の英語表現。** 公式サンプル問題に現れる言い回しを、シナリオの書き出し（`Production data shows that ...` / `During testing, you observe that ...`）と設問の型（`What change would most effectively address ...` / `What is the most likely root cause?` / `What's the most effective first step ...`）に分けて示してください。特に `most effectively` `most likely` `first step` といった限定語が、どの判断軸を問うているかの対応を明示してください。

**(13) 今後の課題。** 5ドメインの配点比率に対して学習量が不足している領域と、英文法上まだ出会えていない項目（純粋な完了時制、AP1A〜AP1E の形容詞＋to不定詞など）を明示してください。

各スライドは、暗記用の羅列ではなく「判断できること」を目標にしてください。専門用語は初出時に必ず定義を添えてください。英語の原文を引用する場合は、必ず日本語訳を併記してください。ソースに情報がない箇所や断定できない箇所は、無理に埋めず「ソース内に記載なし」と明示し、推測で補わないでください。

## 補足：このプロンプトの設計意図

**判断の3軸を独立したスライドにした理由**：CCAR-F は「暗記ではなく判断を問う」試験であり、公式サンプル問題12問のうち10問が判断を問う設計になっている。3軸を最初に押さえておくと、以降の機能比較スライドも「どの軸で選ぶか」という視点で読める。

**設定スコープを独立させた理由**：Domain 3 の 3.1（設定の階層とスコープ）は出題の中核でありながら、`~/.claude/` と `.claude/` のように文字面が似ていて混同しやすい。表で並べて差分を可視化する価値が高い。

**アンチパターンを独立させた理由**：公式ガイドが `Avoiding anti-patterns such as ...` と明示的に名指ししたものは、選択肢問題で誤答として現れやすい構造になっている。正解のパターンだけでなく、誤答のパターンを覚えておくほうが選択時に迷わない。

**試験特有の英語表現を入れた理由**：本番は英語で出題される。技術知識があっても、`first step` という限定語が「過剰設計を排除せよ」という指示だと読めなければ、正解を選び損ねる。英文法の学習と試験対策が交差する箇所である。

**ソース内に記載なしを明示させる理由**：NotebookLM が推測で埋めると、蓄積したログにない情報が混入し、何を学んだかの記録として信頼できなくなる。空白は空白として残すほうが、次に何を読むべきかが分かる。
